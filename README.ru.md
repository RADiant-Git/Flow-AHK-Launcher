Плагин [Flow Launcher](https://flowlauncher.com), который превращает нажатие клавиши или короткую
формулу в переназначение [AutoHotkey v2](https://www.autohotkey.com/):

```text
key new alt + shift + !c -> esc
```

Набрали формулу → нажали `Enter` → правило скомпилировано в скрипт AutoHotkey v2, разобрано
`AutoHotkey.exe /validate` и применено на лету. Не нужно писать `.ahk`-файл, перезапускать скрипт и
открывать окно настроек.

```text
🎯 Записать переназначение        запись нажатием
🔒 Записать в режиме удержания    нативный ремап AutoHotkey
➕ Собрать правило из каталога…    конструктор или формула
❓ Справка и управление хуками     пауза, перезапуск, автозапуск
```

*Главный экран ровно в том виде, в каком его возвращает плагин: карточка на действие, затем по
карточке на правило.*

---

## Возможности

- ⌨️ **Запись нажатием** — нажмите клавишу, сочетание или кнопку мыши, и они запишутся точно:
  включая `XButton1` и `Ctrl + Alt + Shift + Win`.
- 🔒 **Режим удержания** — нативный ремап AutoHotkey: целевая клавиша ведёт себя как настоящая,
  работает автоповтор и сочетания с модификаторами.
- 🔓 **Прозрачность** — по умолчанию правило забирает исходное нажатие; для отдельного правила его
  можно пропускать и в активное окно.
- 🌍 **Область действия** — правило работает везде или только внутри выбранного процесса
  (`Code.exe`, `chrome.exe`, …).
- ✅ **Проверка до применения** — `/validate` разбирает скрипт без выполнения, поэтому битый скрипт
  никогда не заменяет работающий.
- 🔄 **Видимое расхождение** — плагин хранит хэш применённого скрипта и сам сообщает, когда
  запущенные хуки отстали от правил.
- 🧩 **Простые данные** — правила лежат в одном читаемом JSON-файле, а не в непрозрачном блобе
  настроек.
- 📦 **Без зависимостей** — только стандартная библиотека Python; AutoHotkey v2 — единственное, что
  нужно поставить отдельно.

## Установка

**Из магазина плагинов**

```text
pm install FlowKey Manager
```

**Вручную** — скачайте `FlowKeyManager.zip` со
[страницы релизов](https://github.com/RADiant-Git/Flow-AHK-Launcher/releases/latest) и либо выполните
`pm install <путь к архиву>`, либо распакуйте его в
`%APPDATA%\FlowLauncher\Plugins\FlowKeyManager\`.

**Из исходников**

```cmd
git clone https://github.com/RADiant-Git/Flow-AHK-Launcher.git "%APPDATA%\FlowLauncher\Plugins\FlowKeyManager"
```

После этого перезапустите Flow Launcher (`Ctrl + R` в строке поиска). Ключевое слово — `key`, его
можно изменить в настройках плагина.

## Синтаксис

```text
[@процесс] <триггер> [ + <триггер> ... ] -> <действие>
```

Формула идёт после `key new`, поэтому целиком запрос выглядит так:
`key new alt + shift + !c -> esc`.

| Формула | Результат |
| :--- | :--- |
| `w -> esc` | `W` нажимает `Escape` |
| `alt + shift + c -> esc` | `Alt + Shift + C` нажимает `Escape` |
| `alt + !c -> esc` | **Удержание**: `Alt + C` ведёт себя как `Escape` |
| `@Code.exe alt + c -> esc` | Только в VS Code |
| `w -> ^ew` | Действие как Send-последовательность |
| `w -> Media_Play_Pause` | Мультимедийная клавиша |

Модификаторы: `ctrl`, `alt`, `shift`, `win` (и `l`/`r`-варианты). `!` перед именем последней клавиши
включает режим удержания.

### Два режима действия

| Режим | Генерируется | Когда |
| :--- | :--- | :--- |
| `send` | `*w::Send('{Escape}')` | Одиночное нажатие целевой клавиши |
| `remap` | `*w::Escape` | Целевая клавиша ведёт себя как настоящая: автоповтор, работа с модификаторами |

В `remap` годится только имя одиночной клавиши. Если указать последовательность, плагин применит её
через `send` и честно об этом сообщит.

### Имя клавиши и Send-строка

Имена из каталога (`esc`, `F5`, `Volume_Up`) сворачиваются к каноническому виду и оборачиваются в
фигурные скобки: без них AutoHotkey печатает слово «Volume_Up». Сочетание тоже разбирается
правильно — записанное нажатием `^AppsKey` уйдёт в `Send('^{AppsKey}')`. Это важно: `^` в Send
действует на **следующий символ**, поэтому `Send('^AppsKey')` нажимает `Ctrl + Shift + A`
(заглавная — через Shift) и печатает остаток `ppsKey` текстом. То же с любым модификатором: `+PgUp`,
`#e`. Алиасы после модификатора тоже канонизируются: `^apps` → `^AppsKey`.

Всё остальное уходит в `Send` как есть: `^ew`, `{LCtrl down}e{LCtrl up}w`, `текст`.

Модификатор как одиночное действие (`w -> ctrl`) отвергается: `Send('{LCtrl}')` нажимает и сразу
отпускает — эффекта нет. Для такого смысла нужен режим удержания.

### Кому достаётся нажатие

По умолчанию правило **забирает** исходное нажатие: AutoHotkey не пропускает его дальше, то есть
`XButton1` не сделает «Назад» в браузере — сработает только ваше переназначение. **Прозрачность**
меняет это: нажатие уходит и в активное окно, поэтому срабатывает и переназначение, и штатная
функция клавиши. Такое правило помечено 🔓 в списке.

Результат переназначения — обычные синтетические нажатия, и другие скрипты AutoHotkey на них
реагируют. Прозрачность несовместима с удержанием: ремап сам превращает исходную клавишу в целевую,
пропускать ему нечего.

## Примеры

| Задача | Команда |
| :--- | :--- |
| Переназначить `W` на `Escape` | `key new w -> esc` |
| Удержание `Alt + C` как `Escape` | `key new alt + !c -> esc` |
| Только в VS Code | `key new @Code.exe alt + c -> esc` |
| Play/pause на `Ctrl + Alt + T` | `key new ctrl + alt + t -> Media_Play_Pause` |
| Сырая Send-последовательность | `key new w -> ^ew` |
| Записать клавишу, не зная её имени | `key` → 🎯 Записать переназначение |
| Записать правило с нуля, включая кнопку мыши | `key` → 🎯, нажать `XButton1`, выбрать действие |

## Поиск и управление

| Ввод | Результат |
| :--- | :--- |
| `key` | главный экран: три действия, затем все правила |
| `key ?` | справка и управление хуками |
| `key new` | конструктор |
| `key new w -> esc` | конструктор с готовой карточкой «✅ Применить» |
| `key <текст>` | фильтр действий и правил по имени, триггеру, действию или окну |
| `key target: …` | переход к шагу выбора действия |
| `key app: …` | выбор процесса-окна |

`Enter` по строке правила переключает его; подпись говорит, в какую сторону. В контекстном меню
(`Shift + Enter`, `Ctrl + O` или ПКМ по результату):

- **Включить / выключить правило** — то же, что `Enter` по строке.
- **Прозрачность** — пропускать исходное нажатие в окно.
- **Удалить правило** — намеренно последним пунктом.

Экран справки (`key ?`) ставит все хуки на паузу, применяет их заново, переключает автозапуск при
входе в Windows, открывает папку плагина и очищает все правила.

## Как это работает

```text
Flow Launcher -> main.py -> core/rpc.py -> core/services.py -> core/ahk/codegen.py -> runtime.ahk
```

- `core/rpc.py` — граница JSON-RPC. Он нормализует любую форму `argv`, рассылает по явной таблице
  методов и не даёт процессу упасть: исключение превращается в карточку с причиной.
- `core/model.py` владеет валидацией, поэтому некорректное или конфликтующее правило отклоняется
  **до** записи на диск. Молча не работающих правил не бывает.
- `core/ahk/codegen.py` — чистая функция из `RuleSet` в текст скрипта; именно поэтому домен
  тестируется без установленного AutoHotkey.
- Порядок применения: сгенерировать → `AutoHotkey.exe /validate` (разбор без выполнения) → записать
  `runtime.ahk` → запустить. `#SingleInstance Force` вытесняет предыдущий процесс.
- Пустой набор правил не генерирует ни одного хоткея, поэтому резидентный процесс AutoHotkey с
  глобальным клавиатурным хуком не остаётся.

Границы слоёв и обоснование текущего дизайна: [ARCHITECTURE.md](ARCHITECTURE.md).

### Данные

Правила и состояние лежат **вне папки плагина** — в каталоге настроек плагина Flow Launcher:

```text
%APPDATA%\FlowLauncher\Settings\Plugins\FlowKey Manager\
    modules.json      правила — единственный источник правды
    session.json      стадия мастера, пауза, замечания, хэш применённого скрипта
    runtime.ahk       сгенерированный скрипт хуков
```

В портативной установке Flow Launcher используется
`<папка программы>\UserData\Settings\Plugins\FlowKey Manager\`.

Это не косметика. Flow Launcher обновляет плагин так: распаковывает новую версию в соседнюю папку и
удаляет старую целиком, поэтому всё, что лежит внутри папки плагина, гибнет при каждом обновлении.
Каталог настроек переживает и обновление, и удаление плагина с сохранением настроек.

`modules.json` версионируется и правится руками; шаблон — [`modules.json.example`](modules.json.example):

```json
{
  "format_version": 2,
  "rules": [
    {
      "id": "0f1c2b3a",
      "name": "Ctrl + Alt + T ➔ Media_Play_Pause",
      "trigger": "^!t",
      "action": "Media_Play_Pause",
      "scope": "*",
      "mode": "send",
      "enabled": true,
      "transparent": false
    }
  ]
}
```

| Поле | Что значит |
| :--- | :--- |
| `id` | короткая метка, нужна только для навигации по интерфейсу |
| `name` | подпись правила в списке; на поведение не влияет |
| `trigger` | AHK-спецификатор **без** `*`: `^!t`, `w`, `XButton1` |
| `action` | имя клавиши каталога либо готовая Send-последовательность |
| `scope` | `*` (везде) или имя процесса: `Code.exe` |
| `mode` | `send` или `remap` |
| `enabled` | участвует ли правило в генерации скрипта |
| `transparent` | `~`: исходное нажатие уходит и в активное окно |

Файл формата v1 (плоский список с `trigger_ahk` / `target` / `app` / `hold`) мигрируется при первом
чтении, а битая отдельная запись пропускается без потери остальных. Оба файла перезаписываются
атомарно под файловой блокировкой: Flow Launcher запускает новый процесс на каждое взаимодействие.

## Если что-то не работает

- **Правило в списке есть, но ничего не делает.** Посмотрите карточку ⚠️ наверху главного экрана:
  там причина, например триггер уже занят другим правилом. Если написано 🔄 Хуки отстают от правил —
  нажмите на неё `Enter`.
- **Набранная формула ничего не делает.** Голая формула трактуется как фильтр. Конструктору нужен
  префикс `new`: `key new w -> esc`.
- **Клавиши «залипли».** `key ?` → ⏸️ Приостановить все перехваты, затем 🔄 Перезапустить рантайм AHK.
- **В игре или приложении от администратора ничего не происходит.** AutoHotkey не может отправлять
  нажатия в окно с более высокими правами, чем сам скрипт, а часть игр использует raw input и
  игнорирует синтетические нажатия. Для приложений от администратора запускайте AutoHotkey от
  администратора.
- **После обновления перестал работать автозапуск.** Значение в реестре указывает на папку
  конкретной версии. Включите автозапуск заново: `key ?` → 🚀.
- **Почему при записи блокируется ввод?** Чтобы записываемое сочетание не улетало в активное окно.
  Отмена — `Escape`. Привязать сам `Escape` можно через каталог или формулой (`esc -> ...`), а с
  модификатором (`Ctrl + Esc`) — и нажатием.

## Разработка

```cmd
git clone https://github.com/RADiant-Git/Flow-AHK-Launcher.git
cd Flow-AHK-Launcher
python -m unittest discover -s tests -t .
```

202 теста покрывают домен (валидация, конфликты триггеров, миграция v1→v2), DSL, кодогенерацию,
захват, хранилище (атомарность, откат, BOM), границу RPC (все формы argv, включая список в
`context_menu`), выбор каталога данных и согласованность файлов релиза. AutoHotkey для прогона не
нужен: единственный тест, которому он требуется, пропускается сам.

Плагин говорит на обычном JSON-RPC в stdout, поэтому его можно запустить напрямую:

```cmd
python main.py "{\"method\":\"query\",\"parameters\":[\"new w -> esc\"]}"
```

**Релизы.** Версия берётся из `plugin.json`. Push в `main` запускает
[`publish-release.yml`](.github/workflows/publish-release.yml): он прогоняет тесты, собирает
`FlowKeyManager.zip`, проверяет его раскладку и публикует GitHub Release с тегом `v<версия>`. Магазин
Flow Launcher подхватывает новый релиз сам.

**Отправка в магазин** (один раз): форкните
[Flow-Launcher/Flow.Launcher.PluginsManifest](https://github.com/Flow-Launcher/Flow.Launcher.PluginsManifest),
скопируйте [`store/…json`](store/) в его каталог `plugins/` и откройте pull request. Имя файла должно
остаться `<Name>-<ID>.json` и совпадать с `plugin.json`.
